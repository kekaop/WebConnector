## HTTP

```http
POST /api/grant-pass
X-Shared-Secret: <приватный ключ>
Content-Type: application/json
Idempotency-Key: order-10452
Prefer: respond-async

{"player":"Steve","pass":"premium"}
```

Успешная завершённая операция возвращает 200 с `status: success`, `request_id`, `operation_id`, `operation_request_id`, `replayed` и `result`. Незавершённая операция возвращает 202 с `status: accepted` и теми же идентификаторами. Заголовок `Location` содержит путь статуса. Асинхронность задаётся `async: true` в действии либо заголовком `Prefer: respond-async`.

Статус читается через `GET /api/operations/<UUID>` с тем же именованным ключом. Ответ 200 содержит объект `operation`: `id`, `action`, `created_at`, `state`, `initiator`, `request_id`; после завершения — `completed_at` и `result`. Состояния: `QUEUED`, `RUNNING`, `COMPLETED`, `FAILED`, `CANCELLED`. Ответ 200 на GET означает успешное чтение статуса, а не успех действия. Чужая операция скрывается ответом 404.

| Код | Значение |
| --- | --- |
| 200 / 202 | Завершено / принято в обработку |
| 400 | Ошибка JSON, схемы, размера, заголовка или idempotency key |
| 401 / 403 | Ошибка авторизации / запрещено политикой |
| 404 / 405 | Нет доступного маршрута / запрещён метод |
| 409 | Конфликт ключа либо уже выполняется опасное действие |
| 429 | Лимит частоты, очередь или журнал заполнен |
| 500 | Ошибка обработчика, хранилища или сервиса |

Ошибки до запуска содержат `status: error`, `request_id`, `code`, `message`. Ошибки обработчика также содержат `operation_id` и `result`. Каждый запрос получает новый request ID; `operation_request_id` относится к исходному запросу операции.

## Повторные запросы

`Idempotency-Key` содержит 1–128 символов `[A-Za-z0-9._:-]` и действует в пределах стабильного имени клиента для всех действий. Повтор с тем же действием и проверенным JSON возвращает прежнюю операцию. Другой JSON или действие с тем же ключом вызывает 409. Используйте ID заказа, сохраняйте его при сетевых повторах и не меняйте имя ключа при ротации секрета.

Резервирование записывается и сбрасывается на диск до запуска обработчика. После аварии незавершённая операция становится `FAILED/interrupted` и не запускается автоматически снова. Это защита от автоматического повторного выполнения, а не транзакционный откат: часть сторонних команд могла выполниться. При таймауте работающий обработчик может завершиться позже. Перед новым ключом сверяйте заказ и состояние сервера; сохраняйте резервную копию журнала.

## Java API

Подключите `WebConnector-2.0.0-api.jar` как `compileOnly`, объявите `depend: [WebConnector]` и не включайте копию API в свой JAR. Сервис доступен через:

```java
var registration = Bukkit.getServicesManager().getRegistration(WebConnectorAPI.class);
if (registration == null) throw new IllegalStateException("WebConnector unavailable");
WebConnectorAPI api = registration.getProvider();
```

`registerAction(ActionDefinition.builder(...))` задаёт описание, схему, handler, timeout, permission, dangerous, requireIdempotency и exposeHttp. Имена уникальны. По умолчанию обработчик выполняется на основном потоке сервера, а HTTP-публикация выключена. Для фоновой работы без Bukkit используйте `mainThread(false)`. Проверяйте `context.checkDeadline()` между побочными эффектами.

`executeAsync` возвращает future, `submit` — идентификатор либо `Submission`. Перегрузка с `Caller` и idempotency key нужна для заказов и раздельных клиентов. `execute` блокирует поток и запрещён на основном потоке сервера. `Caller.plugin(name)` разрешает обычные локальные действия, но не опасные. Java-плагины являются доверенной частью процесса и не изолируются этой моделью.

Есть `getAction`, `hasAction`, `getActions`, `getOperation`, `getOperations`, `unregisterAction` и `publishEvent`. Регистрируйте события со скалярными JSON-данными, без живых Bukkit-объектов. При отключении удаляйте свои регистрации. Уже принятые операции сохраняют обработчик. Completion callback может выполняться на разных потоках — планируйте Bukkit-вызовы явно. [Компилируемый пример](../../examples/java/) проверяет получение сервиса, регистрацию, приватность и выполнение на основном потоке.

## Webhook

Включите `event-dispatch.enabled`, задайте `signing-secret` и маршруты `event-routes`. Маршрут поддерживает `type`, `endpoint`, `signing-secret`, `headers`, `filters`, `event-class`, `priority`, `ignore-cancelled` и шаблоны `payload`. Фильтры сравнивают строковые значения полей после подстановки. `PlayerFirstJoinEvent` сохранён.

Событие содержит `id`, `type`, `timestamp`, `server`, `data`. Для старого плоского формата NodeDashboard используйте `legacy-payload: true`; подпись добавляется и в этом режиме. Шаблоны `{event.player.name}` читают только public-getters, без произвольных методов и `getClass`.

Заголовки: `X-WebConnector-Id`, `X-WebConnector-Timestamp`, `X-WebConnector-Signature`. Подпись — `sha256=` и hex HMAC-SHA256 от UTF-8 `timestamp + "." + raw_body`. Проверяйте исходные байты до разбора JSON, сравнивайте подпись за постоянное время, ограничивайте возраст и дедуплицируйте по ID события. [Тестовый получатель](../../examples/webhook_receiver.py) показывает алгоритм.

2xx завершает доставку. Сетевые ошибки, 408, 429 и 5xx повторяются с exponential backoff до установленного числа попыток. Другие ответы не повторяются, редиректы не выполняются. При повторе ID, timestamp, тело и подпись не меняются. Порядок не гарантирован. Очередь ограничена и хранится в памяти; выключение плагина может потерять недоставленные события. Для платежей нужен отдельный надёжный журнал бизнес-операций.

## Skript

Собственного аддона нет. Подготовлены отдельные [примеры](../../examples/skript/) для SkJson 6.0.0, SkriptWebAPI v0.1.2 и SkHttp 1.5: JSON POST, заголовки, стабильный ключ заказа, обработка 202/ошибок и GET статуса. Установите только подходящий вашей версии сервера и Skript аддон; основной диапазон WebConnector не означает поддержку этого диапазона сторонним аддоном.

SkJson предоставляет ответ, привязанный к запросу. У SkHttp 1.5 `last response` глобальный: даже при сериализации примера другой скрипт может заменить ответ. Для параллельных заказов предпочтителен SkJson или Java-клиент. SkriptWebAPI использует async-запрос и событие ответа. Нельзя синхронно ждать HTTP на основном потоке, если действие должно выполниться на нём же.

Храните `{webconnector.secret}` в приватной серверной конфигурации, не публикуйте его в `.sk` и не отправляйте игрокам. Примеры доступны только консоли. Синтаксис сверяется с исходниками указанных версий; запуск конкретной комбинации сервер/Skript/аддон проверяется отдельно. Источники и ограничения — в [Skript integration](../SKRIPT.md).
