# Руководство WebConnector

[Главная](../../README.ru.md) · [English](../CONFIGURATION.md) · [API и интеграции](API.md)

## Установка и подключение

Плагин рассчитан на Paper 1.20.1–26.2, с экспериментальной совместимостью 26.3. Для серверов 1.20.1–1.20.4 используйте Java 17, для 1.20.5–1.21.11 — Java 21, для 26.1+ — Java 25. Один JAR использует общий Bukkit API и байткод Java 17; Folia не поддерживается.

Поместите основной JAR в `plugins/` и запустите сервер. При первой установке создаётся конфигурация версии 2 со случайным секретом. Он хранится в `plugins/WebConnector/config.yml` и не выводится в лог. По умолчанию сервер HTTP слушает `127.0.0.1:25575`, а ключ имеет доступ только к `ping`. Для внешнего подключения нужен выделенный порт хостинга либо обратный прокси. Сам плагин не запускает сторонние процессы и не требует отдельной панели.

Адрес, порт, базовый путь и методы задаются в `server.host`, `server.port`, `server.path`, `server.allowed-methods`. Для действий доступны POST/PUT/PATCH, по умолчанию POST. Статус операций всегда читается через GET. При передаче через сеть используйте HTTPS на прокси или приватный защищённый туннель.

## Ключи и доступ

Совместимый общий ключ настраивается полями `security.shared-secret`, `shared-secret-actions`, `shared-secret-permissions`, `shared-secret-allow-dangerous`. Заголовок по умолчанию — `X-Shared-Secret`. Для каждого клиента лучше создать отдельный ключ:

```yaml
security:
  shared-secret: ""
  require-authentication: true
  ip-allowlist: ["127.0.0.1/32", "10.20.0.0/16"]
  api-keys:
    shop:
      enabled: true
      secret: "<случайный приватный секрет длиной не менее 32 символов>"
      expires-at: "2027-01-01T00:00:00Z"
      actions: [grant-pass]
      permissions: [shop.grant]
      allow-dangerous: false
```

Пустой список действий ничего не разрешает; `['*']` разрешает все действия, опубликованные в HTTP. Permissions проверяются отдельно. `expires-at` можно не указывать. Отключённые и просроченные ключи не работают. Имена ключей и активные секреты должны быть уникальны. При ротации меняйте значение секрета, сохраняя имя ключа: имя связывает клиента с операциями и защитой от повторов.

Пустой IP allowlist допускает любой прямой адрес подключения. Заголовки `X-Forwarded-For` не считаются доверенными. При работе через прокси ограничивайте адреса клиентов также на нём. Режим без авторизации разрешён только для loopback при явных `development-mode: true` и `allow-unauthenticated-localhost: true`; опасные действия этому клиенту недоступны.

## Действия и параметры

```yaml
actions:
  grant-pass:
    enabled: true
    expose-http: true
    permission: shop.grant
    require-idempotency: true
    async: true
    timeout-seconds: 10
    validation:
      player: {type: player_name, max-length: 16}
      pass: {type: enum, allowed: [vip, premium]}
    commands:
      - "lp user {player} parent add {pass}"
```

Для примера нужен LuckPerms. Используйте простые имена YAML без точек; Bukkit трактует точки как вложенные разделы. Регистр важен. `operations` зарезервировано. YAML-действия публикуются в HTTP по умолчанию; `expose-http: false` оставляет локальные вызовы. Java-действия, наоборот, по умолчанию приватны.

Типы параметров: `string`, `integer`, `boolean`, `uuid`, `player_name`, `enum`, `regex`. `required` по умолчанию true. Для строк есть `max-length`, для целых — `min` и `max`, для enum — `allowed`, для regex — полный шаблон `pattern`. Неизвестные поля, неверные типы и управляющие символы запрещены. Имя игрока содержит 1–16 латинских букв, цифр или `_`.

Каждый `{параметр}` команды должен иметь правило проверки; `{action}` задаётся системой. Подставляемое значение дополнительно ограничено одним токеном `[A-Za-z0-9_.:-]{1,256}`. Пробелы, селекторы, переводы строк и дополнительные аргументы из JSON не допускаются. Неизменяемую часть команды пишите в конфигурации. Все шаблоны проверяются до первого побочного эффекта, но уже выполненные команды при ошибке следующей команды не откатываются.

Алиасы `player_name`/`name` преобразуются в `player`, а `player_uuid` — в `uuid`, когда канонический параметр есть в схеме. Настройка — `payload.player-name-keys` и `player-uuid-keys`. Одновременная передача алиаса и канонического поля отклоняется.

## Опасные действия и файлы

`shutdown: true` останавливает сервер после `shutdown-delay-ticks` (по умолчанию 20). `delete-files` содержит фиксированные пути относительно папки сервера. Оба механизма автоматически делают действие опасным; другие чувствительные команды помечайте `dangerous: true` вручную.

Удаление требует `files.enabled: true` и явно заданных `files.allowed-roots`. Разрешены только обычные отдельные файлы в выделенных подпапках сервера. Нельзя удалить каталог, корень allowlist, файлы WebConnector, выйти через `..`, symlink или junction. Шаблоны из HTTP в пути не подставляются. Удаление выключено по умолчанию.

HTTP-ключу нужны доступ к действию, его permission и `allow-dangerous: true`. Игроку дополнительно нужен `webconnector.dangerous`; консоль имеет право выполнять опасные действия. Параллельно выполняется только одно опасное действие. При таймауте блокировка сохраняется до фактического завершения обработчика.

## Команды

| Команда `/webconnector` или `/wc` | Permission |
| --- | --- |
| `status`, `actions`, `action <name>`, `operations [id]`, `events` | `webconnector.status` |
| `reload` | `webconnector.reload` |
| `test <action> [JSON] [--key=<id>]` | `webconnector.execute` |
| `diagnostics` | `webconnector.diagnostics` |

`test` действительно выполняет действие. `webconnector.admin` объединяет обычные административные права и по умолчанию доступен операторам, но не включает `webconnector.dangerous`. Права опасных действий и `webconnector.shutdown` по умолчанию выключены.

`reload` проверяет новую конфигурацию и заменяет действия, ключи и маршруты без потери журнала. Java-регистрации сохраняются. Изменение listener/лимитов HTTP, потоков, размера журнала, имени сервера и глобальных параметров отправки требует перезапуска. Уже принятые операции используют исходную конфигурацию. Ошибка загрузки оставляет активную конфигурацию.

## Обновление с 1.x

Остановите сервер и сохраните старый JAR и папку плагина. Версия 2 не переписывает старую конфигурацию автоматически: она откажется запускаться и укажет на миграцию. Создайте новую конфигурацию из образца, затем перенесите проверенные действия.

`plugin-host/port/path` переносятся в `server.host/port/path`; секрет и имя заголовка — в `security`. Добавьте scope действий и permissions, схемы параметров, отдельное разрешение удаления файлов и права опасных действий. Пустой секрет больше не отключает защиту. Ответ `status: ok` заменён на `success`; для незавершённых операций предусмотрен 202 и polling. Старым получателям событий задайте `legacy-payload: true`, добавив секрет подписи.

NodeDashboard сохраняет прежние настраиваемые адреса `/api/<action>`, включая `shutdownNode`. Клиент должен передавать JSON, подходящий ключ и стабильный `Idempotency-Key`; неизвестные поля нужно убрать либо описать в схеме. Полный пример — в [английском руководстве миграции](../MIGRATION.md).

ServerBootstrap подключается через HTTP либо поддерживаемый Java API. WebConnector может отправить заранее заданную команду, но завершение dispatch не означает завершения фоновой задачи другого плагина. Замена мира должна оставаться в корректном стартовом/offline-цикле ServerBootstrap, а не происходить поверх загруженного мира.

## Лимиты, журнал и диагностика

Настройки `limits` ограничивают тело запроса, таймауты, потоки, очередь и частоту по IP, ключу и действию. IP-лимит учитывает неуспешную авторизацию; лимит ключа — запросы статуса. Окна частоты фиксированные, длительностью одну минуту.

`operations.max-records` ограничивает журнал. Завершённые операции без idempotency могут вытесняться; записи с ключом автоматически не удаляются. При заполнении получается `429 journal_full`. Увеличьте размер и перезапустите сервер либо архивируйте терминальные записи на остановленном сервере, согласовав с клиентами запрет повторов старых заказов. Удалённый ключ сможет выполнить действие снова. Не очищайте журнал ради сброса ошибки.

Ошибки 401 означают проблемы с ключом; 403 — с scope/IP/permissions; 400 — со схемой/JSON/заголовками; 409 — конфликт ключа либо занятое опасное действие; 429 — лимит/очередь/журнал. При 500, таймауте или `interrupted` проверьте фактическое состояние перед созданием нового ключа. Сохраните request ID и operation ID для сопоставления с логом.

Администраторы и установленные плагины считаются доверенными. Конфигурация и webhook-заголовки содержат секреты; ограничьте доступ к файлам. WebConnector не пишет секреты, тела запросов и сырые исключения обработчиков в лог. Пользовательский Java-обработчик отвечает за безопасность собственных сообщений.

Тесты запускаются через `gradlew build`. Матрица API не равна проверке запуска всех сборок Paper: для настоящего сервера есть [отдельный стенд](../TESTING.md). Его запуск требует явного принятия Minecraft EULA.
